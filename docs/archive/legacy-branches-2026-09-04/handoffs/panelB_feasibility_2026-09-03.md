# Cross-model panel feasibility memo (research agent, 2026-09-03; web-verified, links at the end)

## Recommendation
Do Panel B as a reduced **action-as-token predictor** on the cached DINOv3 tokens using the jepa-wms port `src/models/ac_predictor.py::VisionTransformerPredictorAC` (`img_size=(256,256), patch_size=16, num_frames=4, tubelet_size=1, embed_dim=1024, predictor_embed_dim=512, depth=6, num_heads=8, action_dim=2, action_conditioning="token", is_frame_causal=True, use_rope=True`) inside the existing feature-space trainer; match Panel A's depth/width first, then depth 12 / width 1024 if the loss-equivalence gate passes. This is the class behind the JEPA-WMs authors' "V-JEPA-2-AC(fixed)" baseline (arXiv:2512.24497). The same class exposes `action_conditioning="feature"` (action concatenated to every patch token), so the AdaLN / token / feature three-mechanism series of JEPA-WMs Fig. 5 is available for ≈ 3 extra GPU-h. Drop LeWorldModel and "released driving JEPA" panels.

Verified token layout: one action token + one state token are prepended per frame (`x = cat([a, s, x], dim=2).flatten(1, 2)` → `[B, T*(H*W+2), D]`), linear action/state encoders, block-causal mask via `build_action_block_causal_attention_mask(..., add_tokens=2)`, 3-D RoPE; per-frame actions `[B, T, A]` supported in the jepa-wms port (`action_encoder_inpred=True`). Single forward over the window; **no rollout method** — multi-step unroll must be written as in our trainer's `unroll_eval`. Sequence length 4 × 258 = 1,032 tokens vs 1,024 for Panel A → ≈ the current 20 min/model at depth 6 / width 512; ≈ 1–1.5 GPU-h/model at depth 12 / width 1024. Licence: jepa-wms CC-BY-NC 4.0; the original class in `facebookresearch/vjepa2` is MIT.

Hook adapter for Panel B: sites = per-block residuals at the action/state token positions (indices 0, 1 of each frame block), action→hazard/corridor attention edges, plus the same patch-token groups; `modulation_patch.py` has no analogue — replace with action-token patching.

## LeWorldModel / LeJEPA line (Q1)
LeWM arXiv:2603.19312 (Maes, Le Lidec, Scieur, LeCun, Balestriero). Code `github.com/lucas-maes/le-wm` (MIT); weights HF `quentinll/lewm-{pusht,cube,tworooms,reacher}`. Action-conditioned: yes (`ARPredictor` of AdaLN `ConditionalBlock`s, continuous actions). Encoder ViT-Tiny trained end-to-end from 224 px pixels; `encode` keeps only the CLS token (192-d per frame; "~200× fewer tokens than DINO-WM"). Trained on 10k–20k episodes × 92–200 steps per environment. Training on our 6.4 k frames is ~300× below its regime; no frozen-DINO option in the model code; zero-shot on MetaDrive with a 2-D action: no (environment-specific encoders). LeJEPA arXiv:2511.08544 (`rbalestr-lab/lejepa`, SIGReg library, no world model, no checkpoints); Rectified L_p JEPA arXiv:2602.01456 (`YilunKuang/rectified-lp-jepa`, MIT, image SSL only). **Conclusion: not a panel; SIGReg/RDMReg regularisers are a tier-3 cell on our own predictor.**

## Open action-conditioned JEPA driving WMs with weights (Q2)
None with a low-dimensional ego action. V-JEPA 2-AC (arXiv:2506.09985): DROID 7-D action + 7-D proprio tokens, ViT-g, not zero-shot for a 2-D action. V-JEPA 2.1 (arXiv:2603.14482): encoders only released, no 2.1-AC weights found (unverified). jepa-wms: no AC *training* config exists (only the vj2ac *eval* yaml: `pred_type: vjepa2_ac`, `action_conditioning: token`, depth 24, dim 1024). NWM (arXiv:2412.03572, `facebook/nwm`, CC-BY-NC): CDiT diffusion in SD-VAE latents, actions (u∈R², yaw, time); not JEPA. DINO-world (arXiv:2507.19468): no code/weights found. DriveWorld-VLA, Latent-WAM, DiT world-action model (2606.12987), DA-WAM, RaWMPC: no usable weights or not JEPA. Drive-JEPA (2601.22032): encoder + planner, not an action-conditioned WM. VaViM/VaVAM: open weights, AR token video model, action-free. Vista / Epona: pixel diffusion, ≥ 1 B, irrelevant to a latent-predictor sonar. → keep F12: zero-support anchors stay on the egg.

## Smallest faithful token recipe (Q3)
Original module `vjepa2/src/models/ac_predictor.py::VisionTransformerPredictorAC` (defaults depth 24, dim 1024, heads 16, action_embed_dim 7, RoPE; forward `(x, actions, states, extrinsics=None)`); training config `vjepa2/configs/train/vitg16/droid-256px-8f.yaml` (4 nodes × 8 GPUs, 315 epochs). For precomputed features: skip the encoder and `app/vjepa_droid/train.py`; feed DINOv3 tokens `[B, 4·256, 1024]` to the predictor (`predictor_embed` handles 1024→512); `tubelet_size=1`; per-frame actions `[B,4,2]` plus a state token (ego speed or zeros); write the teacher-forced + 2-step rollout loss as in the AdaLN trainer. `keon/jepa` (MIT) is a readable minimal reference; `facebookresearch/eb_jepa` AC example is a GRU, not faithful.

## Hypotheses for the panel contrast
H1 token-group selectivity depends on action entry (token model: wrong-group recovery < 0.10 with same-group ≥ 0.30; AdaLN 0.61). H2 relational geometry (C1–C2) reproduces under the registered rule. H3 the locus shifts to the action-token residual / action→corridor edges. H4 loss equivalence within 5 %. Alternatives: capacity/optimisation differences (match depth/width/steps and NMSE), RoPE position artefacts (the "feature" variant has no extra tokens), seed variance (3 paired seeds; report per seed), and the F1 template defect (run on v0.8 before any locus claim). Pre-specified minimum effect: wrong-group recovery difference ≥ 0.25 between panels with CI excluding 0.
