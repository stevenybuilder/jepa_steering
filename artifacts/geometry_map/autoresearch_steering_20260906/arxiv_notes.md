# Frozen-world-model steering: literature decision note

Research date: 2026-09-06. Scope: a bounded development-only decision for `autoresearch_steering_20260906`. **Verdict: run a limited pilot.** Confidence is moderate in the diagnosis and low in any particular operator's eventual efficacy. No experiment was run for this note.

The strongest next mechanism is an **action-conditioned correction of systematic forecast error**, followed by a small risk penalty if residual predictability is weak. Keep JEPA-WM weights, candidate plans, native goal, and native scoring formula fixed for the first comparison. The inference is that fitting model-generated behavioral targets can faithfully reproduce the model's mistakes; more expressive geometry alone need not repair this. This is a hypothesis motivated by the supplied negative results, not an established explanation.

Two questions must remain separate: can an intervention predict actual futures better, and does its chosen action improve the physical endpoint? The existing selected-action failures make the second question decisive. Do not duplicate the running chart-pullback or CPU metric-capacity/history-sufficiency work.

## Pilot A: residual correction that predicts consequences rather than desired outcomes

**Hypothesis.** A low-dimensional portion of `actual_encoded_future - frozen_predicted_future` is predictable from the current encoded context and candidate action sequence across TRAIN trajectories. Correcting that portion changes the native argmin in the physically beneficial direction.

1. Fit a TRAIN-only residual basis of at most 16 dimensions. Regress residual coordinates on standardized current-context features, candidate actions, and frozen predicted-future features with ridge regression. Keep a mean-residual-only baseline and an action-only regression ablation. Start with terminal correction at the existing horizon; do not silently change the action horizon.
2. Apply `z_corrected(a) = z_predicted(a) + beta * U * residual_hat(context, a, z_predicted(a))`. Preserve the native visual/proprio weighting when defining norms and computing the unchanged native cost. Use a TRAIN-derived residual-norm cap and a small recorded exploratory dose family, such as beta 0, 0.25, 0.5, 1. Fit all transformations, cap, ridge settings, and seeds before scoring the development states.
3. Primary control is an orthogonal rotation of the predicted residual within the same TRAIN residual span, preserving each candidate's correction norm. Use several prespecified rotations and show all. An additional target-pairing shuffle within TRAIN trajectories tests whether context/action alignment matters. Identity is exact zero correction. Keep goal/context tensors untouched and hash model parameters before and after.
4. Score every original candidate under every arm before reading its physical consequence for evaluation. Report selected-action physical progress, native task outcome, regret, candidate identity, forecast error, and full per-state score vectors. Better forecast MSE without a physical selection gain does not pass.

**Falsifiers and alternatives.** No cross-trajectory residual predictability weakens systematic-correction feasibility. Mean-only performing equally well suggests a global bias, not action-conditioned information. Rotated/shuffled corrections performing equally well suggests generic perturbation sensitivity. Better actual-future prediction without better physical choices points back toward goal-cost mismatch. Lower native cost with worse actual forecasts signals exploitation.

**Available input lead.** `artifacts/geometry_map/pusht_calibration_v1/inputs-v2/MANIFEST.json` declares `fit100 only; validation25 after candidate freeze, confirmation25 remains sealed until authorized`. Inspect the existing data access/extraction contract before loading `train_first150.pt`; a shared payload must not become accidental access to sealed records. If suitable frozen predictions are absent, cache only permitted TRAIN slices. Four-state leave-one-state-out fitting is an alternative cheap exploratory screen, but those folds remain reused development and must never be described as untouched confirmation.

**Cost estimate, not a measurement:** existing cache fitting/scoring should take minutes on CPU or one GPU; caching 100 short TRAIN clips plausibly fits a 0.25–1 GPU-hour first allowance. Measure the first few clips and revise the allowance before scale-up. Full episode evaluation is an additional cost. The reported estimate excludes any new dependencies or dataset transfers.

An output correction is a useful frozen-model baseline but does not by itself establish a specific hidden causal mechanism. If project rules require internal-site steering for promotion, first show the output baseline works, then realize its correction at a validated internal site and compare the two. Label this scope difference explicitly.

## Pilot B: avoid predictable model failures while preserving native goal scoring

**Hypothesis.** A candidate-dependent risk signal predicts forecast failures that the native cost overlooks. Modest pessimism improves actual selected-action outcomes without merely preferring smaller actions.

Fit a scalar forecast-error predictor on TRAIN trajectories, or bootstrap several Pilot-A residual heads by whole trajectory. Use current context, candidate actions, and frozen predictions only. On TRAIN validation, compare predicted risk with actual encoded prediction error. If it does not discriminate errors, reject it before episode evaluation. A cheap baseline is distance from TRAIN action/context support; do not call this a probability of failure.

Score the exact same plans with `native_cost + lambda * risk`, scaled using TRAIN statistics. Record a small fixed lambda family before the development screen. Candidate permutation of the risk vector is a particularly fair sham: it preserves the complete distribution, norm, and mean of score perturbations while removing its action association. Add an action-magnitude-only penalty with matched perturbation scale. Include zero penalty and the original CEM-selected action; a native argmin within a fixed 64-plan bank is not interchangeable with the original CEM planner.

The gate fails if the risk signal is no better than permutation, gains disappear against the action-size baseline, or the selected plan loses physical progress/success. Do not assume an OOD penalty should be maximized: it can suppress necessary contact and exploration. Cached scoring is a minutes-scale diagnostic; any new candidate generation or actual rollout must have its own recorded budget. This is a planner-scoring intervention and control, not proof of hidden-space causal specificity.

## Decision gates and statistical plan

Treat the current four Push-T states as four dependent-data groups, never 256 independent replications. Keep state-paired per-arm results and all exploratory doses/shams. Do not make a significance claim or credible precision claim from four reused states. An all-four win pattern still cannot yield a two-sided exact sign-test p-value below 0.125; candidate-level bootstrapping cannot repair that limitation.

Before running either pilot, name the primary physical endpoint in its protocol. Preserve the established native task outcome; report historical XY/progress proxies separately rather than changing endpoints after observing which one improves. A proposed screening gate is: positive mean physical improvement against native and the mean prespecified sham, no negative mean native-task change, improvement on at least three of four states, and no large harm hidden by the mean. A practical effect threshold and maximum per-state harm must be chosen from task scale/baseline variation before the screen. These are exploratory scheduling gates, not proof of efficacy.

If an arm passes, freeze one candidate and test it in complete development episodes against native, identity, and norm-matched sham using the same starts, simulation seeds, action interface, goal contract, and planner budget. Repeat simulator runs only where they expose stochastic variation; identical deterministic replays add integrity checks, not independent sample size. Keep all eight available Reach-Wall development episodes when applicable, and avoid choosing only previously favorable starts.

Report paired effect sizes with trajectory-level uncertainty once the number of independent episodes supports it, plus the full success contingency table. For later confirmation, use the project's untouched-trajectory/on-policy gates and prespecify sample size or valid sequential rule. Estimate power for the chosen physical effect from independent development variance; if available confirmation cannot resolve that effect, narrow the claim instead of manufacturing significance. Correct across any independently claimed confirmatory comparisons; all adaptive search history remains exploratory.

## Next decision after failure

If residual correction and calibrated risk both fail, use the already-running metric-capacity/oracle-encoding diagnostics to decide whether model error, goal mismatch, or insufficient state information is dominant. Do not implement another curve solely because its model-target loss is smaller. Consider a learned goal descriptor only if those diagnostics show objective headroom and its TRAIN/goal information contract is clean; LEAP's descriptor-only negative result argues for an auxiliary role. If actual-encoding scoring itself selects poor physical actions, correcting forecasts alone cannot solve that objective mismatch.
